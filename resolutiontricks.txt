### 1. Rendering Tricks in the Viewer (Zero Extra Compute)
The easiest way to make a sparse point cloud look dense is to change how we draw it in the browser:
* **Point Splatting / Sprites:** Right now, `THREE.Points` draws tiny 1-pixel squares. If we map a soft, circular gradient texture (a "splat") to each point and increase the point size slightly, the points will blend together. It tricks the brain into seeing continuous surfaces instead of scattered dots.
* **Point Size Attenuation:** We can make points dynamically resize based on camera distance so close objects look solid and far objects don't disappear.

### 2. Tweak the SIFT Feature Limits (Low Compute Cost)
We are currently downscaling the 4K video to `1024px` and capping SIFT at 4,000 features per image to prevent memory crashes. 
* We can increase the resolution limit to `1920px` (1080p).
* We can lower the SIFT `edge_threshold` and `peak_threshold` to force the algorithm to accept weaker features (like smooth roads or skies).
* **Cost:** SIFT extraction will take maybe 15 seconds instead of 5 seconds, but you'll get 2x–3x more 3D points in the final cloud.

### 3. Increase Keyframe FPS (Linear Compute Cost)
We only processed 17 frames for that 8-second video. If we bump the keyframe extraction rate from 2 FPS to 4 or 5 FPS, we get vastly more overlapping viewpoints. 
* More viewpoints = more triangulated 3D points. 
* **Cost:** The pipeline will take about twice as long to run (e.g., 30 seconds instead of 15), but it remains completely CPU-friendly.

### 4. Poisson Surface Reconstruction (Moderate Compute Cost)
Instead of displaying raw points, we can have Python quickly wrap a "skin" over the sparse points using an algorithm called **Poisson Surface Reconstruction**.
* It calculates a continuous 3D mesh (polygons) from your sparse points.
* It only takes a few seconds on an M1 CPU. It might look slightly "blobby" because the input is sparse, but it turns a ghost-like point cloud into a solid physical environment. 

### 5. The "God Tier" CPU Cheat: Monocular Depth
If you want true dense reconstruction without GPU MVS, we can run a tiny, lightweight AI model like **DepthAnything-Small** or **MiDaS-v2** on the CPU.
* It predicts a depth map for each keyframe in milliseconds.
* We take Colmap's camera poses and "push" the depth maps out into 3D space.
* **Result:** A fully dense, colorized 3D point cloud. It takes maybe 1-2 minutes on an M1 Mac, completely bypassing the hours-long dense reconstruction algorithms.
